# Vision de l’application Mansa Client

## 1. Mission

Mansa Client est l’application principale destinée aux particuliers.

Elle ne doit pas être conçue comme un simple wallet ou une copie d’une banque mobile classique. Elle doit devenir le centre financier personnel de l’utilisateur, capable de réunir dans une seule expérience :

- argent ;
- paiements ;
- cartes ;
- épargne ;
- communication ;
- services publics ;
- documents ;
- fidélité ;
- intelligence artificielle ;
- gestion familiale ;
- investissements autorisés ;
- services du quotidien.

L’utilisateur doit pouvoir gérer sa vie financière sans avoir besoin d’installer plusieurs applications différentes.

## 2. Ambition

Mansa Client doit viser une expérience :

- simple pour un nouvel utilisateur ;
- puissante pour un utilisateur avancé ;
- adaptée au Mali et à l’Afrique ;
- capable de fonctionner avec les banques et Mobile Money ;
- utilisable aussi bien par une personne bancarisée que par une personne qui découvre les services financiers numériques ;
- moderne, premium et rassurante ;
- configurable selon les pays, partenaires et réglementations.

L’objectif est que Mansa devienne une application que l’utilisateur ouvre plusieurs fois par jour, pas seulement lorsqu’il veut transférer de l’argent.

## 4. Publics concernés

### Particulier classique

Il souhaite recevoir et envoyer de l’argent, payer, gérer une carte, consulter son solde et suivre ses dépenses.

### Jeune utilisateur

Il peut disposer d’un compte jeune, de limites adaptées, d’un contrôle parental, d’objectifs d’épargne et d’un suivi éducatif.

### Étudiant

Il peut utiliser la carte étudiante, le paiement de scolarité, les bourses, le transport, les documents et les avantages partenaires.

### Famille

Elle peut utiliser le centre familial, les comptes enfants, les autorisations, les transferts internes, les budgets partagés, les cagnottes et les dépenses communes.

### Voyageur

Il peut utiliser le mode voyage, les devises, les cartes virtuelles, la sécurité renforcée, les plafonds temporaires et les pays autorisés.

### Utilisateur professionnel léger

Un particulier ayant une activité ponctuelle peut recevoir des paiements, partager son identifiant Mansa, utiliser un QR personnel et accéder à certaines fonctions limitées sans devenir commerçant complet.

## 5. Principes d’expérience utilisateur

### 5.1 Simplicité progressive

L’application ne doit pas afficher immédiatement toutes les fonctions. Elle doit présenter les fonctions essentielles en priorité, puis les fonctions avancées selon le profil, l’abonnement, le pays et les autorisations.

### 5.2 Personnalisation

L’utilisateur doit pouvoir personnaliser les raccourcis, l’ordre des cartes, les widgets, les catégories visibles, les notifications, la langue, le thème, l’affichage du solde et les fonctions favorites.

### 5.3 Confiance

Chaque action financière doit indiquer clairement le montant, les frais, le destinataire, le moyen de paiement, le statut, les recours et l’accès au support.

### 5.4 Rapidité

Les actions envoyer, demander, payer, scanner, ouvrir une conversation, bloquer une carte, consulter le solde et retrouver une transaction doivent être accessibles en peu d’étapes.

### 5.5 Accessibilité

L’application doit prévoir lecteurs d’écran, contrastes adaptés, tailles de texte, mode sombre, réduction des animations, retours haptiques configurables, messages simples et fonctionnement sur connexion lente.

## 6. Navigation principale

La navigation exacte sera validée lors du design, mais elle doit donner un accès simple aux univers suivants :

- Accueil ;
- Paiements ;
- Messagerie ;
- Cartes ;
- Services ;
- Profil.

L’accueil doit être personnalisable et peut contenir le solde, les actions rapides, l’activité récente, les cartes, les objectifs, les demandes reçues, les alertes, les recommandations Jini et les services favoris.

La messagerie Mansa Connect doit rester un espace principal, et non une fonction cachée.

## 8. Sécurité

L’application Client doit intégrer :

- code PIN ;
- biométrie ;
- double authentification ;
- détection d’appareil ;
- gestion des sessions ;
- alertes de connexion ;
- blocage à distance ;
- confirmation renforcée selon le montant ;
- limites ;
- analyse de risque ;
- délai de sécurité pour certaines actions sensibles ;
- masquage du solde ;
- protection contre les captures si nécessaire ;
- journalisation.

Les règles de sécurité peuvent dépendre du pays, du niveau KYC, du montant, du type d’opération, de l’appareil et du risque détecté.

## 9. Mode faible connexion

L’application doit prévoir chargement léger, compression, cache local sécurisé, reprise après interruption, états clairs, limitation des animations lourdes et synchronisation différée lorsque possible.

Une opération financière ne doit jamais apparaître comme réussie sans confirmation réelle du serveur ou d’un mécanisme hors ligne officiellement prévu.

## 10. Design

Mansa Client doit avoir une identité propre, premium, moderne, élégante, simple, chaleureuse, crédible, adaptée à l’Afrique sans clichés, fluide, cohérente et accessible.

Les animations doivent améliorer la compréhension sans ralentir l’application.

## 11. Super-application modulaire

Mansa Client peut présenter des modules supplémentaires selon le profil : commerce, TPE, annuaire, services publics, investissements, famille ou étudiant. Ils peuvent apparaître comme raccourcis, cartes, liens vers une autre application, mini-modules intégrés ou fonctions activées par abonnement.

L’utilisateur particulier ne doit pas voir des outils professionnels inutiles.

## 12. Administration

L’administration doit pouvoir configurer sans modification du code les modules disponibles, pays, devises, langues, limites, frais, commissions, seuils de sécurité, abonnements, contenus, promotions, accès par profil, ordre de certaines fonctions, messages d’information, maintenance et feature flags.

Toute modification importante doit être tracée.

## 13. Mesure de qualité

L’application doit suivre notamment le taux d’inscription terminé, le taux de KYC terminé, le taux de paiement réussi, le temps moyen d’une action, le taux d’erreur, le taux d’abandon, la stabilité, la performance, la satisfaction, les demandes de support, la fraude détectée et la disponibilité.

Les analytics ne doivent pas collecter plus de données que nécessaire.

## 14. Critères généraux d’acceptation

La vision Client est respectée lorsque :

- l’application n’est pas limitée à un wallet ;
- les fonctions principales sont accessibles rapidement ;
- la messagerie financière est intégrée ;
- l’identifiant unique Mansa fonctionne dans tout l’écosystème ;
- les fonctions avancées restent modulaires ;
- l’utilisateur comprend toujours les frais et statuts ;
- les actions sensibles nécessitent les confirmations adaptées ;
- l’application reste utilisable sur connexion faible ;
- les données personnelles sont protégées ;
- l’administration peut configurer les fonctions prévues ;
- les modules dépendant de partenaires sont clairement indiqués ;
- l’application reste accessible, performante et cohérente.
